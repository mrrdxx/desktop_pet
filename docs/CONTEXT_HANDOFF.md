# 换新对话继续任务

本指南用于开发 AI 更换对话或上下文；不改变既有任务依赖、验收条件和审查门槛。
通常只需更新 STATUS，不必每次新建交接文件。以下两段提示词可以直接复制。

## 第一步：在旧对话完成交接

将下面这段发给旧对话：

```text
我要换新对话继续任务。请停止新增工作，先检查实际代码、已有修改及正在运行的命令，并完成交接：

1. 保存应保留的代码和文档，保留现有修改，不清理、重置、覆盖或回退工作区，不擅自提交、推送。
2. 更新 docs/STATUS.md：当前任务、完成范围、未完成改动、验证证据、未验证项、阻塞及下一步具体动作。区分你实际执行的验证、用户反馈和代码推断。
3. 同步 docs/TASKS.md 和受影响的需求/架构文档，任务状态只在 TASKS 维护。交接不等于完成，不把未验证工作标为 done。
4. 有复杂的失败尝试、临时措施、特殊恢复步骤时，按需写入 docs/handoffs/ 并由 STATUS 链接；已有规格、审查和整改记录直接引用，不重复抄写。
5. 记录尚未关闭的审查问题、整改入口、等待谁处理及原有验收限制，不修改监理报告或代签通过。
6. 有运行中的构建、测试、后台程序或临时资源时，说明用途、是否仍运行及安全接续/清理方式；不要强杀未知进程，不在文档中写密钥。
7. 检查本地文档链接及状态一致性，确保新上下文只读入口、状态和当前任务相关资料就能接手。

完成后简要告诉我：交接已写入哪些文件、还有什么必须先处理、是否可以关闭本对话。此后保持暂停，不与新对话同时修改代码。
```

等待它完成；若还有未保存的编辑内容，先处理好再关闭旧对话。
关闭对话不会自动提交 Git，也不能代替保存文件或同步副本。

## 第二步：新对话打开同一项目目录

默认直接使用原目录 `C:\Users\mrrdxx\Desktop\pet`，让新开发 AI 能读取代码和项目文档。
若换机器、工作树或项目副本，先同步必要源码、文档、资源、未提交修改及引用的证据文件，再核对版本；不要用另一份旧代码覆盖新改动。
Git 不会自动携带未提交内容和被忽略的 artifacts。被 STATUS/交接引用且仍需使用的材料，也要带上或明确标为不可用。
旧对话暂停后再让新对话写代码，避免两个执行者同时修改同一工作区。

## 第三步：在新对话发接手指令

将下面这段发给新对话：

```text
请接手当前项目，不依赖旧聊天记忆。按仓库 AGENTS.md 的流程工作：

1. 阅读 AGENTS.md、docs/STATUS.md 和 docs/TASKS.md 的当前任务，只展开当前阶段及相关需求/架构章节。
2. 按链接读取当前相关交接、审查、整改记录及协作规则，不必通读全部历史。
3. 检查真实代码、已有修改、任务依赖和必要环境；核对文档，不覆盖或丢弃未提交工作。存在 Git 时查看工作区差异。
4. 文档和实现不一致时，以需求及可核实证据判断并记录差异；不凭上一位 AI 的完成声明认定通过，不把现有代码直接当成正确规格。
5. 先简要说明：当前任务、已完成内容、未验证或阻断事项、下一步动作。随后在已有授权和依赖满足的范围内继续，不为普通实现细节等待额外确认。
6. 原验收和监理门槛继续有效，不因换对话重新选型、重建项目、跳过待验证项，或自行关闭审查问题。

完成本轮后按 AGENTS.md 更新文档与交接状态。遇到重要产品决策、额外授权或真正阻塞时提出具体问题，并继续不受影响的工作。
```

用户快速检查接手摘要是否准确；准确且无阻塞即可继续，不需要再粘贴完整旧聊天。
发现偏差时先指出事实及文档位置，让它核实修正，不让错误摘要成为新的事实来源。

## STATUS、handoffs 和整改记录的分工

- STATUS：固定的当前接手入口，简短概括现在在哪里、看哪些文件、下一步是什么。
- handoffs：某次复杂接手的详细附件，例如帮手交还代码；不另建任务状态表，不每轮重复创建。
- remediation：关联审查问题的开发整改、自测及异议，继续写原记录，避免交接时另抄一份。
- reviews：监理原报告及复核记录，换对话不改变编辑边界。

旧交接保存当时背景；当前任务状态以 TASKS 为准，当前事实需要结合 STATUS 指向的规格、代码和证据核实。

## 旧对话意外中断时

仍可使用第三步提示词。新 AI 先检查已保存文件、已有修改和最新证据，再恢复当前状态；缺失的信息明确标为未知。
不要猜测未保存内容或把未完成操作说成成功；仅在影响安全接续或关键判断时向用户询问。
