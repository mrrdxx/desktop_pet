## F-01 整改：四轮 PID 归属补证

### 补证证据

四轮 CSV 的 CPU 累计值（`cpu_ms_total`）在四轮间严格单调递增，证明数据来自同一进程：

| 轮次 | 首样本 cpu_ms | 末样本 cpu_ms | 与上轮衔接 |
|------|--------------|--------------|-----------|
| 空闲 R1 | 1141 | 2406 | 起始 |
| 空闲 R2 | 3094 | 5000 | 2406→3094 递增 |
| 动态 R1 | 12203 | 22703 | 5000→12203 递增 |
| 动态 R2 | 23781 | 29859 | 22703→23781 递增 |

辅助证据：
- 空闲 R1 终端明确输出 PID=65656（启动时 `Run-PerfIsolated.ps1` 打印）
- 应用终端在四轮采集期间持续运行，未重启
- 隔离存档 `accumulatedRuntimeMinutes` 从初始 150.0 增至退出时 181.39（约31分钟，与四轮墙钟总时吻合）

结论：四轮数据均可追溯至 PID=65656，无需重采。

### 脚本整改

文件：`tests/Integration/Collect-Perf.ps1`

整改内容：
1. **显式 PID 入口**：新增 `-TargetPid` 参数，不再使用 `Get-Process -Name $ProcessName | Select-Object -First 1`，避免多 dotnet 进程误选和 PID 复用
2. **CSV 包含 pid 列**：每条样本记录采样进程 PID
3. **元数据保存**：采集开始时写入 `_meta.json`，包含 PID、进程名、启动时间（`StartTime`）、命令行（`Path`/`CommandLine`）、逻辑核数、计时器类型
4. **Stopwatch 单调时钟**：使用 `System.Diagnostics.Stopwatch` 计算 elapsed，墙钟仅作时间戳标签
5. **进程退出/采样错误明确记录**：目标进程退出时在 CSV 写入 `# process exited` 行并停止采集；采样异常时记录错误信息，不只返回成功摘要
