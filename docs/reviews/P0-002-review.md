## F-01：点击/拖动不激活尚未得到实现保障（P1）

- 位置：`src/DesktopPet.App/MainWindow.xaml` 第 13–14 行。
- 现状：只有 Focusable=False 与 ShowActivated=False，没有点击时的非激活处理。
- ShowActivated 约束首次显示；用户选择窗口后仍可正常激活。元素不可聚焦不等于顶层窗口不会成为前台窗口。
- 影响：拖动桌宠可能使正在输入的编辑器丢失前台状态，违反当前验收要求。
- 要求：验证并实现点击/拖动的非激活路径，可评估 WS_EX_NOACTIVATE / WM_MOUSEACTIVATE；不能为保焦点把实体输入一起吞掉。菜单允许按架构临时激活。
- 验证：先在编辑器输入，直接拖动宠物并释放，不再点击编辑器而继续输入，文字仍应进入原编辑器。
- 来源：[ShowActivated](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.showactivated)。

## F-02：拖动混用了屏幕像素与 WPF 逻辑单位（P1）

- 位置：`src/DesktopPet.App/MainWindow.xaml.cs` 第 159–172 行。
- 现状：PointToScreen 结果直接与 Left/Top 相减，再把屏幕移动量赋给 Left/Top，没有 DPI 转换。
- 影响：非 100% 缩放时拖动距离与鼠标不一致，抓取点会漂移；100% 缩放下看不出这个问题。
- 要求：在明确的转换边界内统一单位；至少先修复单屏缩放，跨屏策略与 P0-003 协调，不引入第二套位置约定。
- 验证：100%、150% 下分别从身体固定位置拖动，鼠标与抓取点保持一致；不能只测松手后是否停止。
- 来源：[PointToScreen](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.visual.pointtoscreen)、[Window.Left 的逻辑单位](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.left)。

## F-03：鼠标捕获失败/丢失没有取消路径（P2）

- 位置：`src/DesktopPet.App/MainWindow.xaml.cs` 第 155–183 行，以及 MainWindow.xaml 事件绑定。
- 现状：先设置 _isDragging，再调用 CaptureMouse 并忽略返回值；仅在 MouseLeftButtonUp 清理拖动，没有 LostMouseCapture 处理。
- 影响：捕获被菜单或其他窗口抢走、未收到松键时，内部可能保留错误拖动状态。
- 要求：捕获成功才进入拖动；统一拖动结束/取消入口，在捕获丢失、检测到左键已松开、窗口关闭时清理。不要通过“失去激活就取消”掩盖 F-01。
- 验证：正常拖放、捕获失败/丢失、菜单打断后均可再次拖动，不会在没有新抓取时跟随鼠标。
- 来源：[UIElement 的捕获 API 与事件](https://learn.microsoft.com/en-us/dotnet/api/system.windows.uielement)。
