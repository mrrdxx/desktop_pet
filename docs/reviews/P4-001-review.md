### F-01 高：补计未观测间隔，并用缺测冒充休息

ActivitySession.Tick（约118行）根据当前末次输入是否新鲜将整个 now-prev 加入累计，无长采样间隔丢弃机制。独立测试仅观测1秒活跃，随后间隔两小时且刚发生一次新输入，当场发出提醒。空闲采样失败为 null 时，使用旧 tick 作为空闲起点，缺测超过5分钟会清空已累计值。负输入年龄（未来输入）也被认作活跃，独立测试多计500ms。

请区分有效空闲与不可用样本。长间隔、缺测、非法年龄或回退时丢弃不可靠区间并重新建立基线。累计和提醒只取可靠的活跃区间，空闲清零须有有效空闲信息。测试按正常采样节奏推进，另验证阈值、有效空闲5分钟重置及缺测前后不多计、不误清零、不补发。

### F-02 高：系统睡眠接线常量错误，暂停档启动不继承暂停

ActivitySessionService.OnPowerModeChanged（约162行）判 4/5，App 传实际枚举。当前 .NET 运行时 Suspend=3、Resume=1，独立枚举反例未进入暂停。开发用 4/5 直调只覆盖了自身约定。[Microsoft PowerModes](https://learn.microsoft.com/en-us/dotnet/api/microsoft.win32.powermodes?view=windowsdesktop-10.0)。App 约525行恢复 _isPaused，约573行创建服务时未同步该值，随后 Start 无条件 Resume，暂停存档启动仍可运行作息计时（源码核对）。

按强类型系统通知接线并把启动的既有暂停状态交给服务。让计时、生命周期标志和停止/释放由同一线程串行处理，或提供等效同步，避免系统事件与采样交叉改状态。补真实枚举与模拟交错通知、暂停档启动、恢复和退出验证。真实锁屏/睡眠体验在修正后完成。

### F-03 中：32位输入计数回绕导致时间跳变

InputIdleSampler（约54行）只计算一次 GetTickCount 到单调域的偏移。独立注入末次输入计数跨 uint 边界，转换结果向后跳约42.95亿毫秒。[GetTickCount 回绕](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount)。GetLastInputInfo 仅针对调用的会话，返回的末次输入计数也不保证递增。[GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)。

按既定架构先在相同 Windows 计数域计算考虑回绕的输入年龄，再交给 Core 与当次单调采样一起使用。对读取失败及无法可信解释的读数走缺测路径。补回绕、有效输入年龄和异常样本的可控测试。
