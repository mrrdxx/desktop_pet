# 产品规格 v0.1

性质：分阶段产品规格，包含已交付基础能力及尚未实现的后续需求，不是整体完成声明。需求来自用户讨论；下列量化阈值是可调整的初始建议。
实现状态见 TASKS；技术约束见 ARCHITECTURE。需求用 `R-` 编号，任务用阶段编号。

## 目标与范围

桌宠应让用户觉得角色在屏幕里生活：能回应用户、保留简单情绪、与同伴互动。
优先做好本地规则与动画表达，不默认引入大模型、语音、联网、账号或云端记忆。
首个可运行里程碑是单宠基础；首个有趣里程碑是单宠鼠标互动与记忆；双宠是后续核心目标。

默认只在用户主动启动后运行。开机启动、常驻策略和音效稍后决定。
用户2026-10-24确认暖棕小熊形象及九种静态表情，并授权写入项目；运行资源采用bear-v1，设定和实际映射见 [小熊设计](design/BEAR_CHARACTER.md)。动作扩展暂缓。开心/困倦等素材存在不代表对应自动行为已实现；当前委屈使用独立正面静态表情，背对动作仍按本轮用户要求暂缓。
程序不关闭用户软件、不移动用户窗口，不记录输入内容。未来的使用习惯统计可关闭并可清除。

### 小熊表情的自然观感（D-011）

- 性格方向：安静、柔软，有一点好奇；反应及时，变化克制，结束后恢复平静。身体移动、呼吸起伏、歪头和眼球追踪继续暂缓。
- 待机只用固定中性底图。普通眨眼只改眼睛附近，耳朵、头型、身体、嘴、脚底、阴影及透明轮廓完全相同；不再用舒服笑脸充当闭眼。
- 眨眼顺序：睁眼→半闭→闭眼→半开→睁眼。当前周期220ms，四段为40/70/70/40ms，闭合与打开节奏略有区别。显示帧有更新周期的取整误差，不以单个截图声称精确到毫秒。
- 每轮结束后独立选取3～7秒安静间隔；4%概率额外眨一下，两次之间睁眼140ms，每轮最多两下。切回待机后重新等待，不立即眨眼。暂停冻结当前帧，恢复继续剩余时间；长时间未更新不补演积压眨眼。
- 不用整张小熊透明交叉淡化衔接表情，避免双眼/双轮廓重影。拖动专用温和脸与松手过渡、抚摸成功舒服脸和委屈新素材尚未安排，不凭本段把这些写成已实现。

## R-00 基础桌宠（阶段 0）

- 一个无边框透明宠物窗口，默认置顶但不主动抢走正在使用的软件焦点。
- 宠物实体可点击、可拖动；周围完全透明区域不阻挡下层软件操作。
- 支持明确的退出方式、暂停/恢复以及“找回宠物”。托盘菜单是默认入口。
- 拖动保持抓取点不跳变。阶段 0 松手即停，阶段 2 再启用抛掷。
- 保存位置与基础设置。显示器断开或布局变化后，找回功能能将宠物放入当前可见区域。
- 用简单占位角色和至少两帧动作验证播放机制，正式美术不属于阶段 0 验收。

验收：可启动、看见动作、拖动、操作透明区下的软件、退出；重启恢复可见位置；不能静默留后台进程。

## R-01 鼠标互动（阶段 1）

- 鼠标在实体上停留触发好奇动作；鼠标速度本身不触发受惊、躲避或表情切换。
- 拖动、抚摸、菜单打开、暂停和委屈表达期间不触发悬停动作。
- 初始建议：悬停 1.2 秒触发，连续悬停只触发一次，离开 0.5 秒后重新允许。
- 好奇保持约2秒（本版采用2000ms，落在批准的1.5～2.5秒范围内）后自动回待机，即使鼠标仍停在原处也不反复触发。提前连续离开当前帧可见区域0.3秒后恢复，无需点击；短暂离开后返回不闪回或重播。再次触发仍需连续离开0.5秒、重新驻留1.2秒；“提前退出”和“允许重触发”是两个不同门槛。
- 暂停中画面和好奇剩余时长冻结，恢复后仅累计活跃时间，重新判断离开时段；恢复中的悬停事件不重启仍在进行的好奇。提前退出/到时退出只结束好奇，不覆盖拖动、委屈或其他表情。原INPUT-003的0.5秒退出规则由D-011细化，历史通过结论不改写。
- 用户于2026-10-25明确取消快速移鼠受惊功能，依据见 [D-009](DECISIONS.md#d-009取消快速移鼠受惊功能)。该功能不是暂缓项，不保留速度阈值、距离阈值或甩动冷却等待以后恢复。拖动所用的受惊静态脸保留，不代表鼠标速度触发。

验收：近处/远处高速移动及往返不会触发受惊或躲避；悬停达到1.2秒可触发好奇，持续悬停约2秒后回待机且不重启；提前移开0.3秒恢复，离开0.5秒后才重新允许触发；动作可被拖动打断。

## R-02 情绪与记忆（阶段 1）

- 每只宠物独立保存亲近度和委屈值，初始使用 0-100 的有界数值。中性值为 50。
- 可从小熊任意可见部位按住拖动，包括头顶、双耳和眼睛上方；透明空白不纳入点击命中。身体按下立即拖动，头部按下先区分抚摸与拖动，见 [D-010](DECISIONS.md#d-010头部和双耳允许拖动并保留抚摸)。
- 鼠标在头部交互区按住小幅来回移动累计1秒算一次抚摸。相对最初按下点超过8DIP、单次移动超过8DIP或按住移出头部抚摸区时，接续为拖动；慢速累计移动同样有效，原抓取点和鼠标捕获保持，不把该次拖动结算为抚摸。
- 头部按住未移动或短按松开不增加亲近度。当前抚摸区为图像矩形上1/3且需命中当前帧不透明像素，**不是拖动的排除区**（固定方案，见ARCHITECTURE §8）；角色JSON的per-character区域字段仍待后续阶段加入。
- 抚摸增加亲近度。高亲近主动靠近鼠标由用户于 2026-10-24 明确延后到阶段 2，与移动和物理手感一起实现；本轮 P1-003 先验收情绪记忆。该需求保留，不得高频追逐或遮挡操作，决策见 [D-008](DECISIONS.md#d-008高亲近主动靠近延后到阶段-2)。
- 普通拖动和临时放在屏幕边缘不算欺负。

### 细化参数（P1-003 实现前确定）

- **单次抚摸增量**：+5 亲近度。冷却 2 秒内不重复累计（防止持续微移刷分）。
- **亲近度阈值**：>= 70 为高亲近。主动靠近行为安排在阶段 2，尚未实现，不属于本轮 P1-003 验收；保留靠近冷却 60 秒、不连续追逐的后续规则。
- **委屈值阈值**：>= 80 触发委屈表达。
- **"关在角落"计分规则**：
  - 角落区域：屏幕工作区四角，各占工作区宽高 15% 的矩形范围。
  - 计分条件：5 分钟内至少 3 次主动拖至角落区域，且最后一次停留满 30 秒。
  - 满足条件后一次性 +20 委屈值，然后清空角落计数器。不满足条件（如仅 1-2 次拖至角落、或最后一次未停留满 30 秒）不增加委屈。
  - 角落计数器在超时（5 分钟窗口过期）后自动清空，不跨窗口累计。
  - 普通拖动（非角落区域）和偶尔放在角落（未达到 3 次条件）不增加委屈。
- **委屈表达**：
  - 达到委屈阈值（>= 80）后，标记"待表达"状态并记录当前本地日期，存入存档。
  - 下一个本地日期首次相遇（鼠标进入宠物交互范围）时执行背对用户表达，持续 10 秒后恢复正常。
  - 表达完成后委屈值设为中性值 50（不是减半），清空"待表达"状态。不永久拒绝交互，仍可拖动生气的宠物。
  - 离线衰减不取消已标记的"待表达"状态：即使离线期间委屈值衰减到阈值以下，待表达仍按标记时的状态执行。
  - 表达被拖动打断时，清空"待表达"状态，委屈值设为中性值 50，不在当日重新表达。
- **衰减规则**：
  - 亲近度向中性 50 回落：偏离部分半衰期 7 天（即 newValue = 50 + (value - 50) * 0.5^(elapsedDays / 7)）。
  - 委屈值向中性 50 回落：半衰期 12 小时（即 newValue = 50 + (value - 50) * 0.5^(elapsedHours / 12)）。
  - 衰减目标始终是中性值 50：高于 50 时向下衰减，低于 50 时向上回升，不会因表达后设为 50 而继续变动。
  - 离线衰减与在线衰减采用同一公式；时钟回拨不增加情绪，异常间隔按架构边界处理。
  - 衰减间隔取非负值，初始最大按 30 天计算（沿用 ARCHITECTURE §7）。
  - **暂停语义**：用户通过托盘暂停期间，暂停时段不计入衰减和动作持续时间。恢复后只计算实际活跃时间，不补算暂停间隔。暂停状态下退出再重启时，退出期间同样属于冻结时段，不计入衰减；恢复后的衰减基准前移到重启时刻。未暂停退出时，离线间隔按正常离线衰减计算。
- **存档演进**：state.json 从 v1 演进到 v2，新增以下字段：
  - `affinity` (int, 默认 50)：亲近度。
  - `grievance` (int, 默认 50)：委屈值。
  - `lastDecayUtc` (string|null)：上次衰减计算基准时间（UTC ISO 8601），用于离线衰减计算。
  - `pendingGrievanceExpression` (bool, 默认 false)：是否有待执行的委屈表达。
  - `grievanceExpressionDate` (string|null)：标记待表达的本地日期（yyyy-MM-dd），用于防止同日重复表达。
  - 读取 v1 文件时情绪字段回退默认值（50），`lastDecayUtc` 回退为 `lastSavedUtc`，`pendingGrievanceExpression` 回退 false，`grievanceExpressionDate` 回退 null。
  - v1 的 `schemaVersion` 高于 v2 时的只读保护规则不变。
  - 重启不重复累计委屈或重复表达：角落计数器不持久化（重启后从 0 开始），待表达状态和防重复日期持久化。

验收：重启不清空情绪；普通拖动不触发委屈；测试时钟可直接验证跨天；仍可拖动生气的宠物。
实现本需求前细化单次增量、阈值、角落区域与动作时长，写回本节，不凭实现代码猜产品规则。
## R-03 随机事件（阶段 1）

- 起步只做“从边缘探头”，运势纸条与受惊逃跑随后增加。
- “每天一次”定义为本地自然日内所有宠物合计最多一次，不保证每天发生。
- 默认每天分配一个 20–120 分钟有效运行时间内的候选触发点；到达后以 50% 概率触发一次。
- 当天随机计划、是否尝试、是否触发写入存档；重启不能重新抽取。
- 不合适时延迟至空闲行为期间；当日一直没有机会则跳过，不积压到次日。
- 拖动、社交、休息提醒、暂停期间不启动彩蛋；本地日期回拨不重复发放已用日期的额度。

验收：可用固定随机种子与测试时钟复现；重启不刷事件；双宠共享每日上限。

## R-04 物理体（阶段 2）

- 松手后根据最近拖动轨迹估算速度，形成抛掷、重力下落和边界反弹。
- 低速松手不会猛烈弹飞，速度有上限，落地能最终停止抖动。
- 只碰撞真实显示器可用区域；不能把显示器之间的空洞当作地面。
- 自动隐藏任务栏的处理先用可用工作区边界近似，不能宣称已经识别了真实任务栏表面。
- “站不稳滑下”先作为有边界约束的表演动作；最终位置必须可恢复。
- 拖动优先于一切物理运动；长卡顿和休眠恢复不会造成巨大位移。

验收：反复抛掷后不会卡墙、无限抖动或跑到无法找回的位置；暂停/恢复不会继续积累速度。

## R-05 双宠社交（阶段 3）

- 初版最多两只，同一进程内运行，各有稳定 ID、位置、情绪与关系值。
- 先做追逐和“被拖走后寻找”，再增加争位置、吵架；每个剧情有开始、回应、结束和冷却。
- 一次仅一个双方共享的社交会话；任何一方被拖动、暂停、移除时及时取消。
- 被拖走后另一只在释放后向其最近有效位置寻找，不能在抓取期间不断追到鼠标下。
- 追逐有距离和时间上限；寻找失败或目标离屏时能退出并回到普通行为。
- 争位置与吵架以角色动作表达，不能移动真实软件或妨碍退出。

验收：双方动作配对；打断不残留单边会话；反复开始/打断不死锁；两只不会永久重叠或无限追逐。

## R-06 作息与休息反馈（阶段 4）

- “连续使用”按近期有键鼠输入的活跃会话估算，不等同于连续打字，不统计具体按键。
- 初始建议：空闲连续满 5 分钟视作休息并重置会话；空闲期间不累加活跃时长。
- 活跃累计 2 小时触发打哈欠/伸懒腰及 30 秒休息表演，同一会话不重复轰炸。
- 初版提醒可跳过，穿透输入，不锁键鼠。用户原设想的“强制休息”保留为后续产品选项，未授权在初版实现系统输入封锁。
- 本地 23:30–次日 06:00 进入困倦表现，睡眠深浅以动画表达；用户仍可拖动或暂停。
- 锁屏、睡眠和程序暂停不累计使用时长，恢复时不补发提醒。

验收：假时钟加空闲数据可覆盖阈值；用户离开后不会算成工作；夜间跨天行为正确。

## R-07 窗口栖息（阶段 5A）

- 只选择普通、可见、未最小化的外部顶层窗口；排除本程序、桌面、系统壳窗口及不可读取目标。
- 以可见外框顶部近似栖息面，不承诺识别每个软件的真实标题栏语义。
- 窗口移动时跟随并播放晃动；关闭、最小化、消失或不再适合时安全脱离。
- 被其他窗口遮挡时，初版脱离或隐藏，不表现成悬空站在遮挡窗口上；具体策略在任务开始时确定。
- 不侵入或修改目标进程；全屏和演示场景默认暂停主动靠近。

验收：至少记事本与一个浏览器实测；最大化、快速拖动、关闭、跨屏时无残留无效绑定。

## R-08 窗口攀爬（阶段 5B）

- 依赖 R-07，先做有限范围“靠近窗口边缘→爬行动画→顶部落位”。
- 这是表演式路线，连续沿真实边框寻路作为升级项，不宣称初版已实现。
- 路线执行中窗口变化必须重新检查目标，失败时回到可见区域。

## R-09 习惯学习（阶段 6）

- 区分“程序启动”“解锁/会话恢复”“操作系统开机”，不得混用统计名称。
- 本地保存有限的日期、活跃时间段、应用标识和聚合时长；不保存窗口标题、网页地址、正文或按键。
- 原始事件默认保留 7 天，聚合保留 30 天；提供关闭、清除入口。
- 首版基于时间段频次，样本不足时不预测；先用靠近和气泡反馈表达。
- 精确找到桌面/任务栏软件图标另立可行性任务，失败时退回气泡反馈。

验收：统计可关闭、清除后不复生；区分记录与预测；展示实际依据而不伪称知道用户意图。

## 体验与质量边界

- 所有主动行为有冷却，暂停、找回、退出始终可用。
- 默认静音；先不引入自动联网或模型调用成本。
- 性能先测量再承诺。阶段 0 记录单宠和空闲基线，阶段 3 记录双宠对比；不持续高速读取磁盘或扫描所有窗口。
- 尚未测试的 Windows 版本、多屏排列与缩放，必须明确写“未验证”。
